# GRID Autosport VR launcher

C# WinForms launcher (.NET 10, x64) ported from GRID2VR's launcher shell: header with logo, channel and **?** (F1), selectable status and notice lines, owner-drawn tabs of collapsible sections (remembered in `launcher-window.json`), a responsive two/one-column layout, Modern/Classic themes that follow Windows light/dark and high contrast, and the footer **Launch | Launch VR | Save settings | Restore original files | Open logs**.

Choices are kept by **Save settings** or a launch in `%LOCALAPPDATA%\GRIDAutosportVR\settings.json` (`hudFollowView`, `modernInterface`, `vrRenderScale`; other keys are preserved). **Graphics → VR rendering** sets VR render scale relative to the headset's OpenXR recommended per-eye size; **Refresh headset** and every VR launch read that size from the probe and keep it in `headset.json`, and the launch passes the scaled size to the bridge as `-gasvreyesize`. **Controls → VR** sets the recenter key (`recenterKey`/`recenterModifiers`, default F10; system shortcuts are refused) and **Keep horizon level** (`keepHorizonLevel`), passed as `-gasvrrecenterkey`, `-gasvrrecentermods` and `-gasvrkeephorizon`. **Launch VR** re-runs the launcher as `--play-vr --game-dir FOLDER`: it checks the 32-bit OpenXR runtime, stages the verified VR executable and bridge under a recovery lease, starts the game through Steam and restores the stock files when it exits. **Launcher → Session** chooses the launch mode (`launchMode`: Normal, Practice or Race), `car`, `track`, `laps`, `opponents`, `opponentCars` (same, class or mixed) and `vrCockpit` (start in the cockpit view, passed as `-gasvrcockpit=1`) from the installed `cars/models` and `tracks/locations` folders. For Practice and Race, `--play-vr` writes the session file `GASVR_<session>.xml` (benchmark-style: the player on grid 0, opponents behind with the example benchmark's driver presets) into the game folder, swaps `system/flow.bin` for the guarded flow and adds `-benchmarkAttract GASVR_<session>.xml`, all under the same recovery lease, and restores both afterwards. The guarded flow is the stock file with the three `attract_mode_chosen` decisions sent to the normal player start (research: `tools/practice_flow.py`); the launcher makes it on the player's PC from their own stock file with a pinned 25-byte patch (`PracticeFlow`), checking the input and output hashes. Car names and disciplines come from a table in `RaceSession.cs`; disciplines only group Same discipline opponents. `--write-session --game-dir FOLDER [--settings FILE] OUTPUT` writes the session file the next launch would use, without staging anything. Practice and Race run on the game's benchmark mode, which ignores the pause button; **End session** (shown beside Launch VR while a session runs, also `--end-session --game-dir FOLDER`) asks the game in that folder to close as its window's close button does, ends it after 15 s if it has not, and the session supervisor then restores the files. `--restore-play --game-dir FOLDER` restores an interrupted session and `--inspect` prints the detected installation as JSON.

Build and check without a headset or game launch:

```powershell
dotnet build launcher\GRIDAutosportVR.csproj -c Release
launcher\bin\Release\net10.0-windows\win-x64\GRIDAutosportVR.exe --self-test artifacts\launcher-selftest
pwsh -File capture\verify_play_session.ps1 -LauncherAssembly launcher\bin\Release\net10.0-windows\win-x64\GRIDAutosportVR.dll -StockAvx "<Steam>\steamapps\common\GRID Autosport\GRIDAutosport_avx.exe" -Bridge artifacts\bridge-build\Release\gasxr.dll
dotnet publish launcher\GRIDAutosportVR.csproj -c Release -o artifacts\launcher
```

The self-test uses a temporary data folder and renders every tab, Modern and Classic, at 900 and 600 px to `launcher-*.png` from an off-screen window that never takes focus. With `GASVR_TEST_GAME` set to an installed game folder, the self-test also checks the real catalog and flow patch and stages and restores a Practice session on a temporary copy of the AVX and `flow.bin` (the installation itself is only read). `verify_play_session.ps1` exercises staging and recovery on a copy of the stock executable in a temporary Steam library. The single-file publish places `probe\AutosportXRProbe.exe` and `renderer\gasxr.dll` beside the launcher. Release packages come from `tools\Package.ps1` (see the root README); the installer (`installer\GRIDAutosportVR.iss`) puts the package in `<game>\GRIDAutosportVR` and uses `--discover`, `--check-install` and `--check-uninstall` to suggest the Steam folder and to refuse while the game runs or a VR session's files are staged.
